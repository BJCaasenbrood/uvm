uvm.json Reference

uvm.json describes a project or package. The same file is used for both: when your project is installed as someone else's dependency, uvm reads its uvm.json to find its paths and its own dependencies.

{
  "name": "my_analysis",
  "version": "0.1.0",
  "matlab": ">=R2023a",
  "toolboxes": ["Signal Processing Toolbox"],
  "paths": [".", "plotting"],
  "dependencies": {
    "signal_utils": "^1.2",
    "daq_tools": { "git": "git@git.company.local:lab/daq_tools.git", "tag": "v0.4.0" }
  },
  "registries": [
    { "name": "work", "url": "git@git.company.local:matlab/registry.git" }
  ]
}

All fields are optional. Unknown fields are kept when uvm rewrites the file.

Fields

FieldDefaultMeaning
namefolder name Name of the project or package.
version"" Version of this package. Used when a dependency points at a branch or commit rather than a version tag.
matlabany Supported MATLAB releases, e.g. ">=R2023a". See release constraints. Violations give a warning.
toolboxes[] MathWorks toolboxes the code needs, by the name ver shows, e.g. "Optimization Toolbox". uvm cannot install them, but warns if they are missing.
paths["."] Folders, relative to the package root, that go on the path. Use this when code lives in e.g. src/. Paths may not leave the package.
dependencies{} Packages this one needs; see below.
registries[] Registries to search before the ones in your own config, so a team project works without per-machine setup. See Registries.

Dependencies

Keys are package names. Names must be valid MATLAB identifiers (letters, digits and underscores, starting with a letter), like signal_utils.

From a registry

A string is a version constraint; the git URL comes from a registry:

"signal_utils": "^1.2"
"plot_tools": "*"

From a git repository

An object with a git URL, plus at most one of tag, branch or rev, or a version constraint:

FormResolves to
{"git": URL, "version": "^1.2"}Newest matching version tag. This is the default for {"git": URL} (any version).
{"git": URL, "tag": "v0.4.0"}That tag.
{"git": URL, "branch": "main"}The branch head, locked until --upgrade.
{"git": URL, "rev": "3f9c2a1"}That commit.

URLs can be anything git accepts: git@host:group/repo.git, https://host/group/repo.git, ssh://..., or a local folder. Relative folders in your project's uvm.json are relative to the project root.

Edit uvm.json by hand whenever you like. The next uvm sync notices the change and re-resolves.

uvm.lock

The lock is JSON too, but is written by uvm; don't edit it. For each package it records the name, version, source URL, the tag/branch/commit asked for, the exact commit installed, and the package's paths, toolboxes, release constraint and direct dependencies.
