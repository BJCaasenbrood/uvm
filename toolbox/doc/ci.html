Testing and Continuous Integration

Run the tests

>> uvm test                    % tests/ and its subfolders, or the project root if there is no tests/
>> uvm test tests/unit         % a specific folder or test file
>> results = uvm("test");      % get the matlab.unittest.TestResult array

uvm test syncs the project first, so the tests always run against the locked packages. Without an output argument it raises uvm:testsFailed when any test fails or is incomplete; with an output argument it returns the results and leaves the decision to you.

Frozen mode

On a developer machine, uvm sync re-resolves when uvm.json changed. In CI that would hide a mistake: the build would test versions nobody locked or reviewed. --frozen never touches uvm.lock and fails instead:

SituationError
No uvm.lockuvm:noLock
uvm.json dependencies changed since the lock was writtenuvm:lockOutdated

--frozen works with uvm sync, uvm run and uvm test. The fix is always to run uvm lock locally and commit uvm.lock.

Running MATLAB in CI

matlab -batch exits with status 1 when the command raises an error, which is exactly what CI needs:

matlab -batch "addpath('uvm/toolbox'); uvm test --frozen --junit test-results.xml"

--junit FILE writes a JUnit XML report, which GitLab, Jenkins, Azure DevOps and GitHub can show test by test.

GitLab CI

# .gitlab-ci.yml
test:
  image: mathworks/matlab:r2024a      # or a runner with MATLAB installed
  variables:
    MLM_LICENSE_FILE: "27000@license.company.local"
    UVM_HOME: "$CI_PROJECT_DIR/.uvm-cache"
  cache:
    key: uvm
    paths: [.uvm-cache/]
  before_script:
    - git clone --depth 1 git@git.company.local:tools/uvm.git /opt/uvm
  script:
    - matlab -batch "addpath('/opt/uvm/toolbox'); uvm test --frozen --junit test-results.xml"
  artifacts:
    when: always
    reports:
      junit: test-results.xml

GitHub Actions

# .github/workflows/test.yml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: matlab-actions/setup-matlab@v2
      - uses: matlab-actions/run-command@v2
        with:
          command: addpath('uvm/toolbox'); uvm test --frozen --junit test-results.xml

Tips

  • Cache the packages. Point UVM_HOME into the workspace and cache that folder, as in the GitLab example. With a warm cache and a frozen lock, CI does not contact your git server at all.
  • Access to private packages. The CI job needs read access to every package repository, for example through a deploy key or a CI job token in a git credential helper. uvm never prompts, so missing access fails fast with uvm:gitFailed.
  • Several releases. Run the same job with different MATLAB images to check the matlab range in uvm.json.
