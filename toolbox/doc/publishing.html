Publishing a Package

Any git repository is already a uvm package: without a uvm.json, its root folder goes on the path and it has no dependencies. Add a uvm.json when the code needs more.

1. Describe the package

>> cd ~/work/signal_utils
>> uvm init

Then edit uvm.json:

  • Set paths if the code is not in the repository root, e.g. ["src"]. Tests and examples should stay off the path.
  • List the toolboxes it needs.
  • Widen matlab to the oldest release you support.
  • Add its dependencies with ranges as wide as you can, e.g. "^1.2" rather than "=1.2.3", so it combines well with other packages.

2. Avoid name clashes

MATLAB has one global namespace: if two packages both contain utils.m, only one is visible, and uvm warns with uvm:shadowing. Put functions in a namespace folder named after the package:

signal_utils/
  uvm.json                 "paths": ["src"]
  src/
    +signal_utils/
      bandpass.m           called as signal_utils.bandpass(...)
      envelope.m
  tests/

3. Release a version

git tag v1.3.0
git push origin v1.3.0

Follow semantic versioning: bump the patch number for fixes, the minor number for new features, and the major number when existing code could break. Never move or delete a released tag; projects have its commit in their lock.

4. Make it findable

Add the package to your team's registry so others can run uvm add signal_utils.
