Sharing Your Code

With people who use uvm

Commit uvm.json and uvm.lock and push. Others clone the project and run uvm sync to get exactly your package versions. For reusable code, tag a release so others can uvm add it; see Publishing a Package.

With people who don't: uvm build

uvm build bundles your project with every package in uvm.lock, so the recipient needs neither uvm, git, nor network access.

A zip file

>> uvm build
Built /home/me/my_analysis/dist/my_analysis-0.1.0.zip (3 package(s), 4.2 MB)

The zip contains one folder:

my_analysis-0.1.0/
  ...your project files...
  uvm_packages/export_fig/        every locked package
  uvm_packages/signal_utils/
  setup_my_analysis.m             puts everything on the path
  THIRD_PARTY_LICENSES.md         what is bundled, and under which license

The recipient unzips it and runs:

>> cd my_analysis-0.1.0
>> setup_my_analysis             % setup_my_analysis('remove') undoes it

This suits colleagues, reviewers, and supplementary material for a paper.

A MATLAB toolbox (.mltbx)

>> uvm build --toolbox
>> uvm build --toolbox --no-deps   % only your own code

A .mltbx installs with a double click, appears in the Add-On Manager, and sets up the path itself. uvm fills in the toolbox details from uvm.json:

Toolbox fieldFrom uvm.json
Name, versionname, version
Summary, authordescription, author (optional fields)
Supported releasesmatlab, e.g. ">=R2023a"
Descriptionrequired toolboxes, and with --no-deps the packages to install separately

The toolbox identifier is derived from the project name, so installing a newer build replaces the older one.

What goes in

  • Your files. In a git repository: tracked files plus new files that are not ignored, so anything in .gitignore (data, secrets, scratch files) stays out. Outside git: every file except hidden ones. .uvm/ and the output folder are never included.
  • Packages, exactly as locked, under uvm_packages/, with their own license files. Only the folders their paths name go on the path.

Options

--toolboxBuild a .mltbx instead of a zip.
--no-depsLeave the packages out; the license file lists what to install separately.
--frozenFail if uvm.lock is out of date instead of updating it. Use this for release builds.
--output DIRWrite to DIR instead of dist/ in the project.

Add dist/ to your .gitignore so builds are not committed.

Licenses

Bundling code means redistributing it, so its license applies. uvm detects each package's license from its LICENSE or COPYING file, lists it in THIRD_PARTY_LICENSES.md, and warns when:

  • a package uses a GPL-family license (uvm:copyleft): what you distribute with it must then be offered under the GPL too;
  • a package has no license file (uvm:noLicense): without a license you may not have the right to redistribute it at all.

Detection is a convenience, not legal advice: check the license files themselves.
