uvm

Project and package manager for MATLAB

Syntax

uvm command arguments
uvm("command", "argument", ...)
result = uvm("command", ...)

Both forms are the same: uvm add lib_a is uvm("add", "lib_a"). Use the function form to pass variables or to get a result. Every command accepts --quiet to suppress progress messages.

Project commands

uvm init

uvm init
uvm init --name NAME
uvm init --project

Create uvm.json in the current folder. The name defaults to the folder name made into a valid identifier. --project also runs uvm project.

uvm add

uvm add NAME
uvm add NAME@SPEC
uvm add NAME --version SPEC
uvm add URL
uvm add URL --tag TAG | --branch BRANCH | --rev COMMIT | --version SPEC
uvm add URL --name NAME

Add a dependency, then lock, install and activate. NAME is looked up in the registries; URL is any git URL or a local folder. The package name for a URL is the repository name, unless you give --name.

Without a constraint, uvm picks the newest version and records ^ that version, e.g. "^1.4.0". A repository without version tags is added on its default branch. If anything fails, uvm.json and uvm.lock are left as they were.

uvm remove

uvm remove NAME

Remove a direct dependency and sync. Packages that were only needed by it disappear from the lock.

uvm lock

uvm lock
uvm lock --upgrade

Resolve dependencies and write uvm.lock without installing. Locked versions are kept where they still fit; --upgrade takes the newest allowed versions instead.

uvm sync

uvm sync
uvm sync --upgrade
uvm sync --frozen

Make the environment match the project: lock if uvm.json changed, install missing packages, check toolboxes and releases, and activate. See Projects, Locking and Activation. --frozen installs exactly what uvm.lock says and fails if the lock is missing or out of date, instead of re-resolving; see Frozen mode.

uvm list

uvm list
packages = uvm("list")

Show the locked packages. With an output, returns a struct array with fields name, version, source, kind (semver, tag, branch or rev), ref, commit, paths, toolboxes, matlab and dependencies.

uvm run

uvm run SCRIPT
uvm run SCRIPT --frozen

Sync the project in the current folder, then run SCRIPT in the base workspace.

uvm test

uvm test
uvm test FOLDER
uvm test --frozen --junit FILE
results = uvm("test")

Sync, then run the tests in FOLDER, by default the project's tests folder (or the root if there is none), including subfolders. Without an output argument, raises uvm:testsFailed if any test fails, so matlab -batch exits non-zero. --junit FILE writes a JUnit XML report. See Testing and Continuous Integration.

uvm activate, uvm deactivate

uvm activate
uvm activate FOLDER
uvm deactivate

Put the synced packages of the project containing the current folder (or FOLDER) on the path, or remove them again. Activation only reads local files. With --quiet, activating outside a project does nothing instead of raising an error; this is what the startup hook uses.

uvm project

uvm project
uvm project --remove

Connect the project to a MATLAB project (.prj), creating one in the project root if needed: opening the MATLAB project syncs and activates, closing it deactivates. The hook files are written to resources/uvm/. --remove takes the hooks out again. See MATLAB Projects.

Configuration commands

uvm registry

uvm registry add NAME URL
uvm registry remove NAME
uvm registry list
registries = uvm("registry", "list")

Manage the registries in your user config. Adding an existing name replaces its URL.

uvm cache

uvm cache dir
folder = uvm("cache", "dir")
uvm cache clean

Show the cache folder (UVM_HOME, default ~/.uvm), or delete the downloaded repositories and packages in it.

uvm setup

uvm setup
uvm setup --remove
uvm setup --file FILE

Add a block to startup.m that puts uvm on the path and activates the project in the startup folder. Uses the startup.m on the path, or creates one in userpath. Running it again replaces the block; --remove deletes it and leaves the rest of the file alone.

uvm doc

uvm doc
uvm doc PAGE

Open this documentation. PAGE is one of getting_started, projects, manifest, versions, registries, publishing, ci, troubleshooting or uvm.

uvm version

uvm version
v = uvm("version")

Show the uvm version and the git it uses.

Examples

% Start a project with two dependencies
uvm init
uvm registry add work git@git.company.local:matlab/registry.git
uvm add signal_utils
uvm add git@git.company.local:lab/daq_tools.git --tag v0.4.0

% Pass a variable with the function form
url = "git@git.company.local:lab/" + repoName + ".git";
uvm("add", url, "--branch", "develop")

% In CI, refuse release builds that depend on branches or loose commits
packages = uvm("list");
assert(all(strcmp({packages.kind}, "semver")), "Release builds must use version tags")
