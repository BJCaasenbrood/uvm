Registries and Work Servers

A registry lets people write uvm add signal_utils instead of a full git URL. It is nothing more than a git repository with one file, index.json, so it can live on the same internal git server as your packages and uses the same access control.

Create a registry

  1. Create a repository on your server, e.g. matlab/registry.
  2. Add index.json on its default branch: 
    {
  "packages": {
    "signal_utils": { "url": "git@git.company.local:matlab/signal_utils.git" },
    "daq_tools":    { "url": "git@git.company.local:lab/daq_tools.git" },
    "plot_tools":   "git@git.company.local:matlab/plot_tools.git"
  }
}
    An entry is either an object with a url or just the URL as a string.
  3. Commit and push. To publish a new package later, add a line and push again.

The registry only maps names to repositories. Versions always come from the tags in each package's own repository, so releasing a new version never requires touching the registry.

Use a registry

Per machine:

>> uvm registry add work git@git.company.local:matlab/registry.git
>> uvm registry list
work         git@git.company.local:matlab/registry.git
>> uvm registry remove work

Or per project, so colleagues need no setup at all — add this to uvm.json:

"registries": [
  { "name": "work", "url": "git@git.company.local:matlab/registry.git" }
]

uvm searches the project's registries first, then your own, in order; the first registry listing a name wins.

When the server is contacted

  • A registry is fetched when a name is not in its local copy yet, and on --upgrade.
  • A package repository is fetched when it is first used, when resolving a package that has no locked version, and on --upgrade.
  • uvm sync with an up-to-date lock and a warm cache, and uvm activate, work entirely offline.

Authentication

uvm runs the git installed on your machine, so whatever works for git clone in a terminal works for uvm:

  • SSH (git@host:...): your SSH key and agent. Recommended for work servers.
  • HTTPS: git's credential helper (Git Credential Manager on Windows, the keychain on macOS, credential.helper store or libsecret on Linux). Sign in once in a terminal so the credentials are stored.
  • Proxies and company certificates: configure them in git (http.proxy, http.sslCAInfo).
uvm cannot show git's password prompt inside MATLAB; it switches prompts off so git fails instead of hanging. For the same reason ssh runs in batch mode, so the first connection to a new server fails with "Host key verification failed" instead of asking whether to trust it. If you see an authentication error, run git ls-remote URL in a terminal, fix it there, and try again. If you set GIT_SSH_COMMAND, GIT_SSH or core.sshCommand yourself, uvm leaves your ssh setup alone.
