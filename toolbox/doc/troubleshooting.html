Troubleshooting

All uvm messages have identifiers, so you can catch errors with try/catch and turn individual warnings off, e.g. warning('off', 'uvm:shadowing').

Warnings

IdentifierMeaningWhat to do
uvm:shadowing Two packages (or a package and your project) define a function, script or class with the same name. MATLAB uses whichever is first on the path. Rename, or move the code into a +namespace folder (see Publishing).
uvm:missingToolbox A toolbox listed in some uvm.json is not installed. Install it with the Add-On Explorer, or ask your license administrator.
uvm:matlabRelease The running MATLAB is outside a package's matlab range. Use a supported release, or pick a package version that supports yours.
uvm:notSynced The project was never synced on this machine, or the cache was cleaned. uvm sync
uvm:stale uvm.json or uvm.lock changed since the last sync (for example after git pull). uvm sync
uvm:projectSyncFailed Opening a connected MATLAB project could not sync it; the message says why. Fix the cause, then uvm sync.
uvm:notInstalled A MATLAB project uses uvm, but uvm is not on the path. Install uvm (see Getting Started) and reopen the project.
uvm:noTests uvm test found no tests. Put tests in tests/, or pass the folder: uvm test FOLDER.
uvm:uncheckedConstraint A package pinned to a branch or commit is also required with a version range, which cannot be checked. Pin a version tag instead.

Errors

IdentifierMeaningWhat to do
uvm:noProject No uvm.json in the current folder or above. cd into the project, or uvm init.
uvm:noVersion No version satisfies all requirements. The message lists them. Relax a constraint, or upgrade the package whose requirement is too old.
uvm:sourceConflict The same package name is required from two different URLs. Make everyone use the registry name, or the same URL.
uvm:pinConflict A package is pinned to two different tags/branches/commits. Agree on one.
uvm:unknownPackage A name is not in any registry. Check uvm registry list, or add it by URL.
uvm:noLock --frozen was used, but there is no uvm.lock. Run uvm lock and commit uvm.lock.
uvm:lockOutdated --frozen was used, but uvm.json changed since uvm.lock was written. Run uvm lock and commit uvm.lock.
uvm:testsFailed uvm test ran, and some tests failed or were incomplete. See the test output above the error.
uvm:missingCommit A locked commit no longer exists on the server (history was rewritten). uvm lock --upgrade
uvm:gitFailed git itself failed; its message is included. Often authentication; see below.
uvm:gitNotFound git is not installed or not on the path MATLAB sees. Install git; on Windows, restart MATLAB afterwards.

Authentication failures

uvm cannot answer password prompts. Run the same command in a terminal to see what git needs:

git ls-remote git@git.company.local:matlab/signal_utils.git

"Host key verification failed" means this machine has never connected to the server over SSH. In a terminal, a first connection asks whether to trust the server; inside MATLAB uvm runs ssh in batch mode so it fails instead of waiting for an answer nobody can give. Connect once from a terminal (for example ssh -T git@git.company.local), accept the key, and try again.

Once that works without a prompt (SSH key loaded, or credentials stored by a credential helper), uvm works too. See Authentication.

Starting fresh

>> uvm cache clean     % delete downloaded repositories and packages
>> uvm sync            % download exactly what uvm.lock says

To re-resolve from scratch, delete uvm.lock before uvm sync.
